# 全栈与AI应用学习路线 v2.0

更新：2026-10-23。依据需求底稿、Grok/Claude评审和用户直接确认整合。本版为后续备课基线；具体进度见[交接页](STATUS.md)，讲课执行见[教学规则](TEACHING_RULES.md)。旧九章路线已存档，已完成成果按本版映射复用。

## 1. 已确认目标与约束

- AI应用全栈优先，长期继续拓展技术广度；目标是能理解、实现、验证和维护带AI能力的软件。
- 预计2029年毕业；目标在2027年10月前后有可展示作品与能力证据，准备投递实习。具体年级、出勤资格和招聘开放情况在投递前核实。
- 计划每周十几小时，按约40分钟课段灵活组合；学习者决定何时停止。考试和实际精力留余量，不把聊天跨度当有效投入。
- 长期主作品仍为私人美股双账户只读看板。接受公开演示版与私人真实版共用代码、隔离配置/数据；公开只用虚构资料。
- 从现有项目接续：先定最小骨架和数据归属，在其中实现小功能；学生逐步组织核心代码，允许旧代码、资料与AI辅助。

[需求与事实底稿](REBUILD_BRIEF.md)维护产品用途和未知项；[评审整合记录](REBUILD_DECISIONS.md)说明采用/修正理由。本次改计划没有增加实际功能完成度。

## 2. 系统骨架与实施边界

```text
页面操作 → Vue发请求 → FastAPI查询/校验 → SQLite保存与读取
页面显示 ← 组件接收数据 ← Vue接住回复 ← 后端组织接口返回
                                  ↑
                     有来源的资料 → 模型调用/检索/受控工具
```

- 数据库长期保存账户、快照、持仓、备注及导入/模型记录；后端处理业务、身份和数据检查；Vue保留收到的数据副本、选择及加载状态；组件负责显示和发出操作。
- 当前GET、Vue组件、账户切换和失败处理继续使用。新增首条链路是数据库到已有页面，不重新搭一套相同的演示。
- 教师准备必要数据库/运行支架并说明作用；学生从具体记录、查询、返回到显示逐次实现，陌生机制分课段。
- 主页面演示资产由后端/数据库统一提供；接数据库时解释加载前状态并一次整理重复前端样本。测试素材按用途隔离。
- 账户、快照、持仓先建立最小逻辑关系；按需要逐步讲SQL与实际表。暂沿用已有接口字段，不因命名/风格整理重写功能。
- 固定网址、登录权限、日志和实际备份恢复是交付能力；PostgreSQL、ORM、Docker等具体工具依用途进入。
- API账号/预算、VPS资源、IBKR实盘/模拟盘样本、行情许可及原始AI日志仍待验证。文件导入和演示资料能形成可用版本，真实同步与复杂金融计算按数据条件推进。

## 3. 七章路线与完成标准

共七章，每章四个成果阶段，共28阶段。阶段不等于一节课或一天，工作量不同。由46重组为28不代表课时减少；旧成果保留。每个阶段动手前宣布范围和完成现象。

| 章 | 核心成果 |
| --- | --- |
| 1 稳定骨架与数据库链路 | SQLite数据经现有FastAPI接口到现有Vue页面，能追踪并改一个小需求 |
| 2 可维护的业务功能 | 备注读写、规定文件导入、必要JS补齐与基础类型，自己经历Git提交流程 |
| 3 最小AI复盘 | 基于演示资料做一次真实模型调用，结果有来源、失败和费用可核对 |
| 4 权限与演示交付 | 本人访问控制、公开演示/私人隔离、VPS运行、备份恢复 |
| 5 检索与受控工具 | 从资料中查找依据，让模型调用有限只读能力，验证质量和边界 |
| 6 真实数据与工程完善 | 强化导入、验证同步、数据库实践及可信比较，保留失败路线 |
| 7 投递与长期广度 | 展示本人贡献与排错能力，核对岗位投递，再做不同业务及有用途的技术扩展 |

### 第1章：稳定骨架与数据库链路

| 阶段 | 做什么 | 完成证据 |
| --- | --- | --- |
| 1.1 全图与成果接续 | 用当前一次加载说明数据从哪里来，标出现有组件/接口与缺少的数据库部分 | 在真实文件和一条演示记录上指出链路；教师示范和学生解释分别记，不重装工程 |
| 1.2 最小SQLite关系 | 区分账户、某一时点快照及该时点持仓，准备少量演示记录 | 学生能说明归属，运行一条有明确目标的查询；教师可准备建表/种子脚本，按需要讲字段与关联 |
| 1.3 接回现有页面 | 现有GET从库中读取，保持已懂的返回形状，Vue接收并显示 | 页面读到数据库演示记录；加载/空/失败可见，前端重复资产样本整理完，旧切换/组件仍可用 |
| 1.4 一次端到端变化 | 按实际功能选加一个字段或按一个已存在时点查询等小变化 | 给目标和验收后学生可查资料组织；说明修改位置，验证正常及一个相关边界，记录帮助程度 |

JS取值、列表/字典/对象、作用域、await和执行顺序在这条链上补清。先理解当前数据再写查询，不单独重学整套入门课。数据库读接口至少覆盖正常、空结果/不存在标识中的相关情况，使用隔离演示数据；本章不要求登录或模型。

### 第2章：可维护的业务功能

| 阶段 | 做什么 | 完成证据 |
| --- | --- | --- |
| 2.1 一个完整写操作 | 为账户/证券关联的个人复盘备注新增并读回，复用已学请求与SQL | 保存后页面对应、重启保留；空正文或错误归属标识有反馈，原始持仓/成交不被改写 |
| 2.2 修改与删除 | 在同一备注功能上组织编辑/删除及成功失败反馈 | 页面与数据库一致，未找到的记录有明确结果；已有写法合并练，按需求观察一次迁移 |
| 2.3 最小文件导入 | 导入一种规定格式的演示快照/日志文件，保留来源与批次 | 正确数据可读回，字段/数值错误被反馈，重复导入有明确处理；先一个可控格式，真实券商报表后续适配 |
| 2.4 小范围类型与组织 | 用熟悉接口记录学习基础TypeScript和缺失字段；小组件对照常见Vue3组织写法 | 一处类型错误能解释和修正，独立类型检查通过；接口运行检查仍保留，不整站重写 |

现有Options API继续运行；Composition API/`script setup`的认识与TypeScript初次练习分别分课段，先解释对应关系再应用。Git从本章实际改动随用随学：看差异、提交、推送、查看历史；至少记录一次由学生实际完成的操作，教师代提交不算掌握。必要写接口测试与日志随功能加入，测试数据隔离。

### 第3章：最小AI复盘

| 阶段 | 做什么 | 完成证据 |
| --- | --- | --- |
| 3.1 一次模型调用 | 从后端给模型一小份演示记录，返回简短摘要；直接理解输入/调用/返回 | 在已选合法可用的API或模型服务上完成一次真实调用；凭据和请求在后端，页面能显示结果，记录模型与基本用量 |
| 3.2 有来源的输出 | 把演示决策日志/账户记录及标识送入，约定结构化摘要和引用 | 页面能追溯引用，程序检查返回结构及引用是否存在；区分原始日志与事后分析，缺理由就标缺失 |
| 3.3 失败与成本 | 处理超时、限额、非法/缺字段回复及重复点击 | 有错误反馈和合理调用边界，保留原账户数据；教师协助配置预算/次数限制，避免盲目重复请求 |
| 3.4 小样本核对与变化 | 用固定少量材料检查有据/无据/资料不足情形，再改一个小需求 | 学生说明输入输出、一次失败路径和怎样判断答错；服务停用时账户展示仍可用 |

先理解直接调用，后续有需求再选框架。API账号与预算在3.1备课时确认；无可用服务时可用明确标注的固定回复准备其余连接，但真实调用验收仍标未完成。模型结果保存输入来源/版本等必要记录；不把模型输出当未经核对的真实收益或原始决策。

### 第4章：权限与演示交付

| 阶段 | 做什么 | 完成证据 |
| --- | --- | --- |
| 4.1 本人身份 | 登录、退出与受保护的账户/备注/模型接口，采用届时核对的成熟密码与会话方案 | 隔离身份测试：未登录拒绝、登录可读、退出后拒绝；解释身份怎样随请求被检查 |
| 4.2 归属与演示隔离 | 检查账户及备注归属；同代码区分公开演示和私人运行配置/数据 | 两虚构身份做允许/拒绝测试；演示环境仅有虚构数据，不会读私人库、券商或凭据；模型动态调用有身份/限额控制 |
| 4.3 私人及演示部署 | 先核实VPS资源与既有用途，再落实网址、HTTPS、服务启动及日志 | 在具体发布范围核定后实际访问页面，检查服务恢复和必要权限；公开演示方案已有认可，实际发布尚未执行 |
| 4.4 备份恢复与交付 | 数据/配置备份、异地副本、实际恢复及版本回退 | 在安全隔离位置实际恢复并核对记录；私有资料按需要加密，运行说明可复现，演示不暴露真实资产 |

公开链接是展示方式之一；私有仓库可以继续私有，是否公开源码另按用户决定。页面去掉真实姓名不等于完成数据隔离。本章用原有业务回归检查，不把首次测试推迟到上线之后。备份与日志从首次持久化逐步形成，本章完成部署环境下的验收。

### 第5章：检索与受控工具

| 阶段 | 做什么 | 完成证据 |
| --- | --- | --- |
| 5.1 先查资料再回答 | 从演示历史日志查到相关记录，再交给模型；解释这种检索增强方法的用途 | 返回可追溯材料，查不到就明确不足；先可解释的小检索，向量数据库按实际检索需要再加 |
| 5.2 一项只读工具 | 模型提出查询某账户/时点的请求，由后端验证参数与身份后执行 | 选定有限接口、返回可核对记录；没有交易/转账/任意SQL/服务器管理能力，错误参数被拒绝 |
| 5.3 输入与引用边界 | 检查外部资料中的指令、越权请求、伪造引用与陈旧材料 | 用少量明确例子验证资料作为数据处理、权限仍由程序判断，记录误答与限制 |
| 5.4 质量与流程整合 | 对比检索/工具调用前后在固定问题上的结果、时延和成本 | 能重现一条完整调用链、说明何时应拒答或人工核对；有自然需求变化与本人贡献记录 |

RAG、Agent和框架名使用前先解释。本章先理解资料检索与受控调用，按重复工作或实际岗位需要选择Dify/Coze/LangChain等工具中的一个作对照，避免为列齐名字同时搭多套系统。

### 第6章：真实数据与工程完善

| 阶段 | 做什么 | 完成证据 |
| --- | --- | --- |
| 6.1 导入质量与来源 | 将已做导入适配实际可得文件，处理批次、重复、部分失败和修正 | 相同记录不会反复计入、失败不会留下混合错误数据，来源和修正可追溯；用隔离样本验证 |
| 6.2 接入与持续更新验证 | 在具体授权后分别核查实盘/模拟盘读取、历史/字段/会话/频率，按实测做同步或受限上报 | 有逐项成功/失败/暂缓记录；失败保留上次正确结果并标过期，文件版可继续用，Bot仅有规定提交权限 |
| 6.3 数据库与工程加强 | 用已稳定业务实践一套PostgreSQL/MySQL；结合日志、关键回归、备份和故障处理 | 迁移练习的查询/数据/精度/权限仍正确，能恢复和排错；线上是否切换按资源和实际需要，依赖版本/运维工具届时核对 |
| 6.4 可信历史比较 | 数据足够时处理区间/币种/入出金/费用/缺失与模拟重置，再展示相应收益和回撤 | 明确口径，用具体边界数据核算；缺数据或不可准确计算时如实标缺失/近似，不冒充真实业绩 |

这些是长期主作品能力；实习展示不等待所有真实同步和金融统计完成。精度、时点、归属、缺失值从第1章遇到时就说明，复杂算法在本章有数据后展开。真实账号接入失败不阻止AI演示、投递准备和后续能力练习。

### 第7章：投递与长期广度

## 5. 能力检查与日常教法

- 每个新功能先看业务与整条链路，再看本次小目标；同类字段/操作一起做，新机制逐步解释，核心代码由学生组织。
- 新技术进入前，核对一个真实用途和本次必要前置。一个小验收目标通常可分一至几个课段，不要求整个技术两课学完，也不等待全站完全独立才前进。
- “能独立做一个小功能”的观察口径：给需求和验收，学生可查资料/旧代码/使用AI，能选择修改位置、组织数据、说明执行过程，验证正常和一个相关边界，遇错能复现定位。教师提供核心答案则如实记提示/示范，不按回复1或手写行数评分。
- 薄弱点在后续自然功能中复用，帮助逐渐减少；新API仍先解释。实际项目故障用于排查练习，教学故障示例需标明，避免把人工埋错冒充真实问题。
- 随数据库/写操作/权限/模型加入必要隔离测试与日志，不为普通文字样式逐行写测试。证据区分源码、真实HTTP、脚本、实际页面和用户报告。
- AI输出要知道改动位置、影响和验证方法。学生会利用AI解决需求可记录为协作能力，仍注明哪些代码由AI生成。

每周十几小时为计划投入，学习与准备实习到岗时间分开；有效时间尚未累计，不把一年直接折成某个保证课时。API账号/预算、VPS和真实数据验证按进入对应功能时确认。需要真实账户/公开发布的具体操作按已认可范围准备并核对，不在本次文档重构时执行。

## 7. 计划变更与招聘证据

- 相对稳定的需求放在需求底稿；当前进度只维护交接页；教法集中维护规则；历史课堂和外部评审单独保留。
- 日常理解问题调整例子、任务大小和提示，不自动改课程主线；章末复盘成果、帮助与缺口。约两个月未完成一章时也复盘，或在出现明确业务/技术阻碍时处理。
- 技术主线改变应写明需求/岗位/项目证据、学习成本、保留成果和影响范围。模型升级先评估怎样改善分工与验证，不因新名字自动更换技术。
- 招聘判断核对目标城市、岗位层级、原始来源、时间与资格；官方支持、项目实践和岗位价值分别判断。两份评审样本覆盖有限，未逐项验证的结论不写成市场份额或“最适合全部岗位”。
- 本轮重构已形成实施基线与近期安排，之后按实际代码推进。五部分评审用来检查具体问题，不把继续写计划当作学习成果。
