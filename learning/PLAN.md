# 全栈与AI应用学习路线 v2.2：最终执行基线

定稿日期：2026-10-24。教学方式确定为“先明确全系统分工，在完整功能实现中学习，卡点原位补清”。保留Vue/FastAPI/SQLite、七章29阶段与已有成果。本版已整合三份教学评审和后续复核；依据见[取舍记录](TEACHING_REVIEW_DECISIONS_2026-10-24.md)，当前事实见[交接页](STATUS.md)。一份阅读完整计划见[最终执行版](FINAL_PLAN.md)。

## 1. 目标与安排原则

- 优先AI应用全栈：理解需求，组织前端、后端、数据库、模型和运行维护，能解释、修改、验证并交付小功能；长期增加技术广度和自学迁移能力。
- 预计2029年毕业，目标2027年10月前后准备投实习，关注广深沪及沿海城市；具体届别资格、到岗天数与开放岗位按实际核实。
- 每周计划十几小时，约40分钟为参考课段，用户决定停止。一个阶段可跨多课；先记录实际投入与帮助，再校准窗口。
- 主作品为私人美股双账户只读看板，公开虚构演示版与私人真实版共用代码，隔离配置、数据库和凭据。网站读取、保存、展示与分析，交易执行在外部。
- 先确定全产品的简单分工图、数据归属、主要连接和待验证依赖，再建立最小可运行链路；学生在同一系统里完成真实功能，教师在需要时讲知识、准备必要支架并标注贡献。既有组件、接口和查询直接接续。
- 每项新机制先解释用途、执行者、输入、中间值和结果；熟悉同类改动合并任务。允许查资料与AI，评价学生的组织、判断和验证能力。

招聘目标、作品功能和教学节奏一起决定取舍。技术栈、章节数和月份是实施方案；已有成果与能力证据保留。当前不追求一次列完所有技术，按具体用途逐步增加。

## 2. 全系统分工与逐步成型

先读一页[系统地图](../ARCHITECTURE.md)：数据来源 → 接入/检查/转换 → 数据库 → 后端查询/业务处理 → Vue状态 → 组件显示；AI读资料并由后端校验保存结果，身份/归属与部署/日志/备份支持整套系统。地图标出已实现、缺口及未知，不提前实现全部模块。

这张全图从开工就存在；课堂在其中持续完成一个完整可见的功能。新知识出现在实际需要的位置，解释后继续原任务。局部补练用于明确卡点，完成后接回功能；不再安排先造一套独立演示系统、之后搬回主项目的默认路线。

当前完整任务：数据库中双账户基本资料、最新快照和对应持仓 → 既有`/accounts` → 既有Vue及组件。可先把一个账户贯穿做通，再复用另一账户，但一直围绕同一个完整目标。基本资料、时点净值、持仓同类字段合并处理；新查询机制按需要解释。现有1.2快照查询已完成，不重新搭单表练习。

持久数据在数据库，后端负责查询/检查/返回，Vue保存收到的副本与界面状态，组件显示并发出操作。教师先展示实际三表/记录和[完整返回目标](DATABASE_MAP.md)，学生组织熟悉字段。保持`demo_paper`、`netvalue`、`holding`等既有名称和组件约定；调整时明确理由、消费者与迁移成本。

真实来源与页面之间设置清楚的接入边界：外部记录先检查/转换/保存，读取接口使用项目内部约定。这个设计用于减少改动，不能保证IBKR接入后表结构/接口/页面完全不变。最小真实样本核对从第1章接库期间开始准备，在2.3接入方案定型前完成可行性判断；实盘与模拟盘分别记录实际授权、字段、时点和历史/更新约束。当前尚未取样，教师可协助准备，用户不必先学完所有券商接口。

演示数据由可复现种子提供，供学习和公开演示使用。当前Vue重复初始资产在接库时整理，同时处理未加载、加载、空、失败与已有数据保留；不能只把对象改成空数组而忽略模板读取。前端本地样本可用于独立组件/测试，明确用途，不在主页面并排维护另一套业务来源。

### 第1章：稳定骨架与数据库链路

| 阶段 | 做什么 | 完成证据 |
| --- | --- | --- |
| 1.1 全图与运行入口 | 明确全系统分工及当前缺口，对照App.vue/main.py追踪请求；沿用本项目独立环境和运行入口 | 能指出主要文件、数据去向和服务地址；在学生实际终端完成启动/查看日志，支架与帮助另记 |
| 1.2 单表查询到快照接口 | 教师准备最小SQLite演示支架；学生先查询snapshots的一条/多条记录，再用account_id参数筛选，最后组装既有快照返回 | `/accounts/paper/snapshots`真实返回来自库的数据，字段不变；正常/无匹配有明确结果，可解释参数和一条返回值 |
| 1.3 完整账户接回页面 | 实现数据库双账户最新状态与持仓到现有页面；沿实际实现观察中间值，组装/accounts原结构 | 页面显示库中数据；初始未加载/加载/空/失败可见，切换仍可用，重复前端资产样本整理完成 |
| 1.4 一次端到端变化 | 从已经接通的数据中选一个小需求，如显示一个字段或查询已有时点 | 给目标和验收后可查资料组织，说明修改位置；验证正常和一个相关边界，记录实际帮助 |

1.2按“打开连接和确定文件→查询并看结果→按条件筛选→将行变成字典→接入路由”逐次讲，不同时要求掌握JOIN、对象嵌套、序列化和新抽象。使用现有`demo_paper`及`netvalue`，参数化查询按实际输入演示，连接关闭及错误处理讲清。教师可准备连接/路径支架，学生逐步理解；不得声称尚未准备的库已经存在。[Python sqlite3参数绑定](https://docs.python.org/3.14/library/sqlite3.html#how-to-use-placeholders-to-bind-values-in-sql-queries)。

1.1/1.2已有成果和帮助证据保留，当前直接接续1.3。完整目标及实现顺序为：

1. 从已有基本资料查询继续，依次查询最新快照及该快照持仓，组装完整模拟账户；单行取下标前检查结果是否存在，全部所需查询结束后关闭连接。
2. 完整模拟账户验证通过后，用account_id参数复用查询与组装，读取实盘账户；保持/accounts的现有键名及模拟盘、实盘返回顺序。
3. 先验证完整接口回复，再改Vue的未加载、加载、空、失败状态与显示条件，并清理重复初始资产；最后验证页面切换和显示。
4. 通过后进入1.4，用一次自然需求变化观察迁移，允许参考旧代码。课堂可跨多课，始终完成同一个目标；新知识出现时就地解释。


1.3使用前约定：账户不存在的404及detail、缺快照与空持仓的不同含义、数据库异常与前端反馈；保留现有框架错误并检查前端能处理的实际形状，不搭通用错误框架。涉及金额计算前核对十进制精度/舍入，时间查询前核对时区和最新的含义；现有快照是带时区的演示时点，未验证真实交易日。第1章阶段收尾复用一次学生自己说明数据从哪里来、经过谁、显示在哪的证据，允许看资料，不每次提交考试。

### 第3章：最小AI复盘

| 阶段 | 做什么 | 完成证据 |
| --- | --- | --- |
| 3.1 一次真实模型调用 | 后端发送少量虚构记录，页面显示简短回复；先讲请求/上下文/模型/返回的对应关系 | 实际可用API或模型服务完成调用，凭据仅后端；记录模型、用量及输入来源，限制输入/输出和重复请求 |

| 3.3 失败与成本 | 处理超时、限额、无效输出、重复点击和受控重试 | 有反馈、保留账户数据；服务器落实调用次数/并发或预算上限，日志可定位且不泄露凭据 |
| 3.4 固定样本核对与小变化 | 用少量有据/无据/缺失材料核对内容，再变更一个小目标 | 能解释输入、输出、失败和判断错误的依据；模型停用不影响账户展示和已保存记录 |

GitHub代码审查/分支与自动化检查按一次实际发布需要练习，教师可配置最小工作流，学生读失败日志并修复一个可解释的问题。备份从首次持久化就保留必要副本，本阶段验收部署环境下的实际恢复。源码是否公开另按用户决定。

## 4. 怎样判断能否开始投实习

阶段百分比只报告成果。允许资料/AI辅助，分别记录代码来源、教师提示与学生的判断、组织和验证：

- **功能证据**：给一个目标，能选修改位置，把数据到页面的小变化做通，验证正常与一个相关边界。
- **排错证据**：能复现一次问题，根据终端/请求/返回缩小范围，说明修复和回归；必要帮助如实记录。
- **交付证据**：演示可访问、使用虚构数据，有身份/归属和费用边界、运行说明与恢复记录。
- **AI证据**：能解释模型收到什么、资料来自哪里、输出怎样核对、超时/无据时怎么办；检索/工具要求按岗位判断。
- **贡献与资格**：讲清本人决策和AI/教师辅助，核对届别与出勤；一次解释准确只是证据之一。

第1章收尾由教师先做少量真实JD的届别/出勤初筛，目标2026年11月底前完成首次核对；未知信息照实保留，不把目标当已完成。第4章完成后做第一次正式岗位匹配复核，有符合条件的岗位可开始准备/投递。第5章完成后形成更完整的AI应用展示并再次复核。以上是内部作品检查点，不是所有企业统一标准；第6章真实同步/复杂统计、7.3/7.4不作为投递前置。

### 最初两三课的试用与核对

- 持续实现同一个完整账户显示任务：在现有基本资料查询上补所选最新快照及对应持仓，复用到另一账户，接既有Vue并处理初始/空/失败。每课结束记录准确停点，后课接着做，不为分课另建练习项目。
- 在实际卡点展示一条数据经过查询行、后端对象、HTTP回复、Vue状态和组件的变化。学生熟悉的映射和重复操作合并做，新机制用当前代码局部解释；教师贡献如实标注。
- 自然讨论/排错/一次小变化留理解证据，选当时合适的方法，不强制每课预测、关代码口述、固定十分钟练习或三项考试。隔几天遇到同类需求时允许查旧代码，观察帮助需求。
- 试用后共同核对：能否知道当前位置、说明数据去向、选择修改位置，是否逐渐减少关键提示。效果不佳先检查解释、跨度、支架、代劳和疲劳，再调整，不凭两三节课宣称模式已证明有效。
