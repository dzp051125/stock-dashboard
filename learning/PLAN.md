## 1. 目标与安排原则

- 优先AI应用全栈：理解需求，组织前端、后端、数据库、模型和运行维护，能解释、修改、验证并交付小功能；长期增加技术广度和自学迁移能力。
- 预计2029年毕业，目标2027年10月前后准备投实习，关注广深沪及沿海城市；具体届别资格、到岗天数与开放岗位按实际核实。
- 每周计划十几小时，约40分钟为参考课段，用户决定停止。一个阶段可跨多课；先记录实际投入与帮助，再校准窗口。
- 主作品为私人美股双账户只读看板，公开虚构演示版与私人真实版共用代码，隔离配置、数据库和凭据。网站读取、保存、展示与分析，交易执行在外部。
- 先定最小整体骨架与数据归属，再在相应位置学习实现；复用现有Vue组件、接口和学习记录项目经验。学生逐步组织核心代码，教师准备必要支架并标注贡献。
- 每项新机制先解释用途、执行者、输入、中间值和结果；熟悉同类改动合并任务。允许查资料与AI，评价学生的组织、判断和验证能力。

招聘目标、作品功能和教学节奏一起决定取舍。技术栈、章节数和月份是实施方案；已有成果与能力证据保留。当前不追求一次列完所有技术，按具体用途逐步增加。

## 2. 固定的整体骨架

```text
页面操作 → Vue发请求 → FastAPI检查/处理 → SQLite查询或保存
页面显示 ← 组件显示 ← Vue保存回复副本 ← 后端组织返回

文件导入 → 后端校验 → 数据库
数据库中有来源的资料 → 后端调用模型 → 校验并保存结果 → 页面
```

数据库持久保存账户、快照、持仓、备注与复盘记录；后端负责查询、业务检查、身份归属和外部服务；Vue保存接口回复副本、选择及加载状态；组件显示并发出用户操作。日后换数据库或增加模型功能，沿这些连接扩展。

账户→某一时点快照→该时点持仓先画清归属。教师可准备最小建表/种子数据/连接支架，说明路径、数据和限制，后续遇到对应需求再讲建表、主外键、事务和迁移。首次动手只查一张快照表，关联查询与嵌套组装分步推进。

现有快照接口是`/accounts/paper/snapshots`，示例账户标识是`demo_paper`，返回键为`account_id`、`as_of`、`netvalue`，净值保持字符串。路径中的paper表示该演示账户入口，不等于数据库里存的账户标识。先保持现有接口形状；需要变更时明确消费者和迁移原因。

前端重复写死资产在主接口接库时集中整理：初始未加载、等待、空结果和失败分别说明；没有数据时组件须有显示条件。已有正确数据才谈失败后保留，不用伪造账户对象顶替未加载状态。

### 第1章：稳定骨架与数据库链路

| 阶段 | 做什么 | 完成证据 |
| --- | --- | --- |
| 1.1 全图与运行入口 | 对照现有App.vue/main.py追踪一次请求，识别缺少的数据库；在本项目建立独立.venv并核对pnpm入口 | 能指出主要文件、数据去向和服务地址；在学生实际终端完成启动/查看日志，支架与帮助另记 |
| 1.2 单表查询到快照接口 | 教师准备最小SQLite演示支架；学生先查询snapshots的一条/多条记录，再用account_id参数筛选，最后组装既有快照返回 | `/accounts/paper/snapshots`真实返回来自库的数据，字段不变；正常/无匹配有明确结果，可解释参数和一条返回值 |
| 1.3 主接口接回现有页面 | 先账户/快照，再持仓；逐次观察查询结果、组装/accounts原结构，复用Vue请求与组件 | 页面显示库中数据；初始未加载/加载/空/失败可见，切换仍可用，重复前端资产样本整理完成 |
| 1.4 一次端到端变化 | 从已经接通的数据中选一个小需求，如显示一个字段或查询已有时点 | 给目标和验收后可查资料组织，说明修改位置；验证正常和一个相关边界，记录实际帮助 |

1.2按“打开连接和确定文件→查询并看结果→按条件筛选→将行变成字典→接入路由”逐次讲，不同时要求掌握JOIN、对象嵌套、序列化和新抽象。使用现有`demo_paper`及`netvalue`，参数化查询按实际输入演示，连接关闭及错误处理讲清。教师可准备连接/路径支架，学生逐步理解；不得声称尚未准备的库已经存在。[Python sqlite3参数绑定](https://docs.python.org/3.14/library/sqlite3.html#how-to-use-placeholders-to-bind-values-in-sql-queries)。

1.3连接主页面不靠一个巨大多表答案照抄。先展示每个中间结果，再组织外层账户和内层持仓，必要时分多课。1.4的小目标以实际已经显示的数据为准，不能布置尚无对应页面的“简单新增字段”。

### 第3章：最小AI复盘

| 阶段 | 做什么 | 完成证据 |
| --- | --- | --- |
| 3.1 一次真实模型调用 | 后端发送少量虚构记录，页面显示简短回复；先讲请求/上下文/模型/返回的对应关系 | 实际可用API或模型服务完成调用，凭据仅后端；记录模型、用量及输入来源，限制输入/输出和重复请求 |
| 3.2 有来源并可保存的输出 | 约定摘要、引用标识和资料不足状态，检查结构及引用，再存SQLite并读回 | 刷新/重启仍能看到结果及原资料引用；原始日志与事后分析分清，引用存在不等于结论正确 |
| 3.3 失败与成本 | 处理超时、限额、无效输出、重复点击和受控重试 | 有反馈、保留账户数据；服务器落实调用次数/并发或预算上限，日志可定位且不泄露凭据 |
| 3.4 固定样本核对与小变化 | 用少量有据/无据/缺失材料核对内容，再变更一个小目标 | 能解释输入、输出、失败和判断错误的依据；模型停用不影响账户展示和已保存记录 |

3章只在本机回环地址开发，使用虚构材料，尚未受保护的应用不通过公网或临时隧道发布。3.1备课时确认API可用性/预算，第一次真实调用即设置基本上限，3.3再系统练失败处理。无可用服务可用标注的固定回复练连接，真实调用仍记未完成。落库保存来源标识/版本、模型与提示版本、时间、已校验结果和必要用量，范围随本次复盘需要确定。

GitHub代码审查/分支与自动化检查按一次实际发布需要练习，教师可配置最小工作流，学生读失败日志并修复一个可解释的问题。备份从首次持久化就保留必要副本，本阶段验收部署环境下的实际恢复。源码是否公开另按用户决定。

| 7.4 有用途的技术广度 | 按岗位/学校/兴趣选第二语言或另一前端做熟悉功能对照 | 一次一项新目标，有可运行成果与适用场景解释，不为新技术整站重写 |

7章跨前面章节开展，7.3/7.4是长期广度。学校算法/数据结构、网络、操作系统、数据库及英文文档阅读持续学习，遇到项目联系就补；面试准备按岗位缺口安排，项目不能代替所有基础课程。

## 4. 怎样判断能否开始投实习

阶段百分比只报告成果。允许资料/AI辅助，分别记录代码来源、教师提示与学生的判断、组织和验证：

- **功能证据**：给一个目标，能选修改位置，把数据到页面的小变化做通，验证正常与一个相关边界。
- **排错证据**：能复现一次问题，根据终端/请求/返回缩小范围，说明修复和回归；必要帮助如实记录。
- **交付证据**：演示可访问、使用虚构数据，有身份/归属和费用边界、运行说明与恢复记录。
- **AI证据**：能解释模型收到什么、资料来自哪里、输出怎样核对、超时/无据时怎么办；检索/工具要求按岗位判断。
- **贡献与资格**：讲清本人决策和AI/教师辅助，核对届别与出勤；一次解释准确只是证据之一。

第4章完成后做第一次正式岗位匹配复核，有符合条件的岗位可开始准备/投递。第5章完成后形成更完整的AI应用展示并再次复核。以上是内部作品检查点，不是所有企业统一标准；第6章真实同步/复杂统计、7.3/7.4不作为投递前置。
