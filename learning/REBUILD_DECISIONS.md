# Grok与Claude评审整合记录

日期：2026-10-23。用途：说明新版路线怎样吸收两份评审、哪些建议经过修正、哪些结论仍受证据限制。此文记录规划决策，不增加学习完成度。

## 1. 用户已直接确认

本轮由用户直接回答“四项都已确认”：

- AI应用全栈优先，同时保留长期技术广度。
- 目标在2027年10月前后具备作品与能力证据，准备投递实习。
- 计划每周投入十几小时；每天时间仍不固定，以约40分钟课段灵活组合。
- 接受公开演示版与私人真实版共用代码、隔离配置和数据的方案。

2029年毕业仍为既有背景。具体年级、可连续实习月份及每周到岗天数未核实；学习时间不能替代出勤承诺。公开演示方案认可不等于网站已经发布，模型API账号/预算也尚未确认。

## 2. 采用与修正

| 议题 | 两份评审的有益部分 | 整合决定 |
| --- | --- | --- |
| 稳定需求与最小骨架 | 都主张保留成果、先完整数据流、按需增加能力 | 沿现有Vue/FastAPI项目补数据库链路；已有GET、组件和状态处理复用，先明确职责 |
| 第一条链路 | Grok提出双账户GET，Claude提出SQLite到页面 | 双账户GET与显示已经存在；新增成果明确为SQLite查询→现有接口→现有Vue，避免重建同一演示 |
| 能力证据 | 都强调独立小改动、帮助程度和数据流解释 | 用自然端到端变化检查；允许旧代码/文档/AI，核心组织与验证责任由学生承担，记录真实帮助 |
| JS薄弱点 | Claude要求在真实问题中补基础 | 取值、作用域、执行顺序随当前功能补，不重学整套入门课；同类写法合并 |
| 主栈 | 两份都建议延续当前栈 | Vue3/Vite、Python/FastAPI、SQLite作为当前实施基线；选择依据是已有基础与复用成本，不声称市场最优或最大份额 |
| AI进入时机 | Grok强调自然业务用途，Claude后续版建议前移 | 数据链路与一个小功能稳定后进入最小模型复盘；再学有来源检索和受控工具，不等全部第二语言/真实同步结束 |
| 文件导入和金融范围 | 都建议真实券商依赖后置 | 近期用演示数据/规定格式文件形成实用版；精度、归属、时点、零与缺失从首次涉及就解释，复杂收益口径后续实测 |
| 公开作品 | Claude建议公开演示版 | 采用同代码不同配置/数据/凭据的隔离方案；公开只用虚构资料，演示不会访问私人数据库或真实券商 |
| 测试与日志 | Claude草案把基础测试放较后 | 修正：数据库/写操作从出现起做必要隔离检查；身份、归属、模型失败随功能加测。日志从需要定位问题时加入，后期整合 |
| 部署、备份 | Grok后续版将其列可选 | 修正：固定网址、权限与实际恢复是作品交付目标；特定数据库和运维工具可比较，能力不删除 |
| 数据库模型 | Claude提出一张快照表含持仓 | 用账户/快照/持仓的最小逻辑关系讲归属，SQLite物理保存结构再按查询需要说明；不把表名或JSON塞入一表当固定要求，也不一课堆复杂ORM |
| TypeScript与Vue风格 | 评审建议后续工程写法 | TS从熟悉接口数据小范围进入；现有Options API继续运行，常见Composition API在小组件中对照学习，不突然整站重写 |
| 第二语言/框架 | 两份都建议按用途后置 | 保留长期广度模块；Java/Go及React等按目标岗位、学校、项目需要选范围，不当作近期AI作品先决条件，也不永久删除 |
| 进入条件 | 两份强调先具备同类功能能力 | 核对本次新机制的必要前置，允许局部提示继续；不要求全站完全独立后才学下一项，避免检查点变无限停留 |
| 时间盒 | Claude提醒规划拖延 | 本轮形成可执行v2和后面三次目标；重构文件本身不计学习成果，随后沿首条数据库链路实施，日常调整任务分量，章末再复盘路线 |

## 3. 招聘证据怎样使用

Grok和Claude粘贴稿都没有附完整逐条原始链接，不足以复核完整样本数、城市覆盖和去重状态。Claude明确标出旧岗位、硕士/多年经验及列表摘要，证据边界较清楚，但其共通项和趋势仍需逐项核对，不能直接推广到全部AI岗位。

当前教师先前抽查已记录于Grok核对文件：Linksome职位正文可读，包含多种后端语言选择、React/Vue、数据库/接口、系统思维；它支持一个具体岗位的要求，不能推出Python在所有AI全栈中占比最高。其他原始岗位有抓取失败、转载或日期不明，继续标待核实。

本轮不把“FastAPI第三方版本号”“AI工具迅速变必需”“近三个月岗位全部如此”等表述写成已证实结论。官方资料用于版本/用法和迁移核对，岗位与项目资料用于技术用途、要求和成本判断；证据不足处保留范围限制。

## 4. 本轮路线结果

新版分七章、每章四阶段，共28个成果阶段：稳定数据链路→可维护业务→最小AI复盘→权限和演示交付→检索与受控工具→真实数据/工程完善→投递与长期广度。

这是内容重新分组，阶段工作量不等，不由46变28推断课时减少。旧1—3章已运行成果映射到新章节继续复用；旧4.1的字段显示和两快照GET保留，独立程度分别记录。计划变更没有实现SQLite、登录、公开部署或模型调用。

2027年10月为准备投递的目标窗口，按实际完成和岗位资格滚动核对；不承诺收到实习offer。API账号/预算、VPS资源、真实IBKR样本、行情许可与原始AI日志仍是待验证条件。
